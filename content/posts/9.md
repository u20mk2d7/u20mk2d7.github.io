Numerical and Mathematical Libraries

For the mathematical layer of the trading system, I use several libraries for different types of numerical workloads. The goal is to keep the low-latency market-data and order-book path simple while providing more advanced numerical tools for research, statistics, and quantitative models.

Eigen — Linear Algebra

Eigen
 is a C++ template library for linear algebra.

It provides functionality for:

Vectors and matrices

Matrix decompositions

Linear systems

Eigenvalue problems

Sparse matrices

Numerical solvers

For a trading system, Eigen can be useful for statistical models, covariance matrices, regression, portfolio calculations, optimization, and other quantitative algorithms.

Example:

Eigen::MatrixXd A;
Eigen::VectorXd x;

Eigen::VectorXd y = A * x;


I would use Eigen mainly in the strategy, research, risk, and quantitative layers rather than directly inside the SBE/FIX market-data hot path.

Boost.Math — Mathematical and Statistical Functions

Boost.Math
 provides mathematical and statistical functions for C++.

It includes functionality for:

Probability distributions

Special functions

Statistical calculations

Mathematical functions

Numerical algorithms

This is useful when implementing quantitative models that require more than the standard C++ math library.

For example, a strategy may need probability distributions, cumulative distribution functions, special functions, or other statistical calculations.

Boost.Multiprecision — High-Precision Calculations

Boost.Multiprecision
 provides arbitrary-precision integer and floating-point types.

I use this type of library primarily for:

High-precision research

Numerical validation

Testing

Reference implementations

Comparing results against lower-precision implementations

For example:

using Decimal = boost::multiprecision::cpp_dec_float_50;


This should generally not be placed directly in the latency-critical order-book path. The purpose is to provide a high-precision reference when numerical accuracy is more important than execution latency.

MPFR and GMP

MPFR
 provides arbitrary-precision floating-point arithmetic with correct rounding, while GMP
 provides high-performance arbitrary-precision integer and rational arithmetic.

Boost.Math can work with high-precision types such as MPFR through its bindings.

For new C++ projects, however, Boost's documentation recommends using Boost.Multiprecision with GMP/MPFR backends rather than directly using the older Boost.Math MPFR bindings.

This gives the application a consistent C++ interface while allowing the underlying high-precision implementation to be selected when required.

A simplified structure is:

Boost.Math
     │
     ▼
Boost.Multiprecision
     │
     ├── GMP backend
     │
     └── MPFR backend


This is particularly useful for creating a high-precision reference implementation and comparing its results with the faster numerical implementation used in production.

BLAS and LAPACK

BLAS
 and LAPACK
 are widely used standards/libraries for numerical linear algebra.

BLAS provides fundamental operations such as:

Vector operations

Matrix-vector multiplication

Matrix-matrix multiplication

LAPACK provides higher-level numerical linear algebra algorithms such as:

Matrix factorization

Linear equation solvers

Eigenvalue problems

Singular value decomposition

These libraries are particularly useful when the application performs significant matrix and vector calculations.

OpenBLAS

OpenBLAS
 is an optimized implementation of the BLAS API with support for different CPU architectures and instruction sets.

The relationship can be viewed approximately as:

             Application
                  │
          ┌───────┴────────┐
          │                │
        Eigen          Armadillo
          │                │
          └───────┬────────┘
                  │
            BLAS / LAPACK
                  │
             OpenBLAS
                  │
                  ▼
              CPU
          ┌───────┴───────┐
          │               │
        Intel            AMD
        x86-64           x86-64


However, this diagram should not be interpreted as saying that Eigen always requires OpenBLAS. Eigen contains its own optimized implementations for many operations and can optionally use external BLAS/LAPACK implementations depending on the configuration and workload.

The important distinction is that Eigen, BLAS, LAPACK, and OpenBLAS operate at different levels.

Eigen — C++ linear-algebra API and algorithms

BLAS — low-level linear-algebra interface

LAPACK — higher-level numerical linear-algebra algorithms

OpenBLAS — optimized implementation of BLAS, with LAPACK functionality also available

For my trading system, these libraries belong primarily to the quantitative, research, statistics, and risk layers. The SBE/FIX decoder and order-book implementation can continue using compact integer or fixed-point representations for predictable low-latency processing.
