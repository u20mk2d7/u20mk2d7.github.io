# Fixing LLVM 19 libc++ and glibc `va_list` Compilation Errors on Linux

## 1. Problem Description

When compiling modern C++ projects on Linux using **Clang 19**, **LLVM libc++ 19**, and **GNU glibc**, you may encounter compilation errors inside libc++'s internal locale fallback header:

```text
/usr/lib/llvm-19/include/c++/v1/__locale_dir/locale_base_api/bsd_locale_fallbacks.h:119:15:

error: no matching function for call to 'vsscanf'

error: cannot initialize a parameter of type '__va_list_tag *'
with an lvalue of type 'va_list'
```

These errors may appear when building projects using modern C++ language standards, such as C++20 or C++26.

The affected internal functions include:

- `__libcpp_snprintf_l`
- `__libcpp_asprintf_l`
- `__libcpp_sscanf_l`

## 2. Why Does This Happen?

### 2.1. `va_list` Type Representation on Linux

On x86-64 Linux systems using glibc, `va_list` is commonly defined as an array type containing one `__va_list_tag` structure.

Conceptually, its definition looks like this:

```cpp
typedef struct __va_list_tag {
    unsigned int gp_offset;
    unsigned int fp_offset;
    void *overflow_arg_area;
    void *reg_save_area;
} __va_list_tag;

typedef __va_list_tag va_list[1];
```

The glibc variadic functions, including `vsnprintf()`, `vasprintf()`, and `vsscanf()`, accept arguments of type `va_list`.

Array-to-pointer conversion normally applies when an array expression is passed to a function. Therefore, the problem should not be described simply as Clang refusing to convert an array into a pointer.

The exact incompatibility depends on the declarations and types used by the compiler, libc++ headers, and glibc headers.

### 2.2. libc++ Fallback Wrappers

LLVM libc++ provides fallback implementations for locale-related functions.

For example, the `__libcpp_sscanf_l` wrapper follows this general pattern:

```cpp
inline int __libcpp_sscanf_l(
    const char* __s,
    locale_t __l,
    const char* __format,
    ...) {

    va_list __va;

    va_start(__va, __format);

    __libcpp_locale_guard __current(__l);

    int __res = vsscanf(__s, __format, __va);

    va_end(__va);

    return __res;
}
```

Similar implementations are used by:

- `__libcpp_snprintf_l`
- `__libcpp_asprintf_l`

The reported compilation error indicates that the compiler cannot match the argument type passed to the corresponding glibc function in the affected compilation environment.

### 2.3. Is This a C++20 or C++26 Issue?

The C++ language standard alone does not establish the root cause.

The issue may involve interactions between:

- Clang's compiler and target configuration.
- LLVM libc++ headers and their fallback implementations.
- glibc's `va_list` definitions and function declarations.
- Platform-specific ABI and compiler compatibility.

Changing from C++26 to C++20 should not automatically be considered a solution.

## 4. Troubleshooting and Verification

Before modifying LLVM or libc++ headers, verify the compilation environment.

### 4.1. Check the Clang Version

```bash
clang++ --version
```

### 4.2. Check the Target Architecture

```bash
uname -m
```

### 4.3. Check the C++ Standard Library

```bash
clang++ -v -E -x c++ /dev/null
```

Inspect the output to identify the include paths and compiler configuration.

### 4.4. Check the Active C++ Standard

```bash
clang++ -std=c++26 -stdlib=libc++ -v -E -x c++ /dev/null
```

### 4.5. Inspect the libc++ Fallback Header

```bash
grep -n -E 'vsscanf|vsnprintf|vasprintf|va_list' \
    /usr/lib/llvm-19/include/c++/v1/__locale_dir/locale_base_api/bsd_locale_fallbacks.h
```

### 4.6. Inspect the glibc `va_list` Declaration

```bash
grep -n -E '__va_list_tag|typedef.*va_list' \
    /usr/include/x86_64-linux-gnu/bits/types/__va_list.h
```

Note: The header location may differ depending on the Linux distribution and target architecture.

## 5. Recommended Approach

Avoid directly modifying system-installed libc++ headers as a permanent solution.

Prefer the following troubleshooting order:

1. Confirm that the compiler is using LLVM libc++ rather than GNU libstdc++.
2. Verify the target architecture and ABI.
3. Check the declarations of `va_list`, `vsnprintf()`, `vasprintf()`, and `vsscanf()` in the system headers.
4. Reproduce the issue using a minimal C++ test case.
5. Check LLVM libc++ updates and upstream patches for the affected version.
6. Apply a compatible upstream fix or distribution patch if one is available.

## 7. Conclusion

This compilation error involves the interaction between libc++'s locale fallback wrappers and the platform's variadic argument-list declarations.

The exact root cause and appropriate fix must be confirmed against the affected LLVM 19 version, glibc headers, compiler configuration, and target ABI.

Do not assume that changing the C++ language standard or manually modifying `va_list` will resolve the underlying compatibility issue.



### The Solution: Upgrading to C++ Variadic Templates
Instead of fighting with C-style va_list, va_start, and va_end macros (which cause endless platform-specific headaches between LLVM and glibc), the most robust solution is to update LLVM's bsd_locale_fallbacks.h to use modern C++ variadic template parameter packs. This completely bypasses va_list type decay issues.

Automated Patch Script
Run the following Python script with sudo permissions to automatically locate and patch the LLVM 19 header file on your Linux system:
```python
sudo python3 -c '
path = "/usr/lib/llvm-19/include/c++/v1/__locale_dir/locale_base_api/bsd_locale_fallbacks.h"
with open(path, "r") as f:
    lines = f.readlines()

new_lines = []
i = 0
replaced = 0
while i < len(lines):
    line = lines[i]
    if "__libcpp_snprintf_l" in line or "__libcpp_asprintf_l" in line or "__libcpp_sscanf_l" in line:
        func_type = line
        brace_count = 0
        started = False
        while i < len(lines):
            brace_count += lines[i].count("{")
            brace_count -= lines[i].count("}")
            if "{" in lines[i]:
                started = True
            i += 1
            if started and brace_count == 0:
                break

        if "snprintf_l" in func_type:
            new_lines.append("template <typename... _Args>\ninline int __libcpp_snprintf_l(char *__s, size_t __n, locale_t __l, const char *__format, _Args&&... __args) {\n    __libcpp_locale_guard __current(__l);\n    return snprintf(__s, __n, __format, __args...);\n}\n")
            replaced += 1
        elif "asprintf_l" in func_type:
            new_lines.append("template <typename... _Args>\ninline int __libcpp_asprintf_l(char **__s, locale_t __l, const char *__format, _Args&&... __args) {\n    __libcpp_locale_guard __current(__l);\n    return asprintf(__s, __format, __args...);\n}\n")
            replaced += 1
        elif "sscanf_l" in func_type:
            new_lines.append("template <typename... _Args>\ninline int __libcpp_sscanf_l(const char *__s, locale_t __l, const char *__format, _Args&&... __args) {\n    __libcpp_locale_guard __current(__l);\n    return sscanf(__s, __format, __args...);\n}\n")
            replaced += 1
    else:
        new_lines.append(line)
        i += 1

with open(path, "w") as f:
    f.writelines(new_lines)
print(f"Successfully patched {replaced} fallback functions with variadic templates!")
'
```
